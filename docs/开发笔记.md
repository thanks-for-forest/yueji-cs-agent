# 开发笔记（决策记录 / 调优过程）

> 记录开发过程中的关键决策、踩坑与量化调优结果，保持可追溯。

## 0. 技术决策记录（ADR）

### ADR-001：LLM 接入采用 OpenAI 兼容协议直连（DeepSeek 主 / Ollama 兜底）
- **背景**：规划文档选定 LangChain；实测 Python 3.14 下 langchain 1.3.16 可安装，但为完全掌控工具调用循环与降级逻辑，Agent 编排层自研。
- **决策**：`src/llm/client.py` 基于 httpx 直连 OpenAI 兼容接口；LangChain 保留在依赖中供后续演进。
- **权衡**：自研 ~250 行，换来工具循环可调试、双提供方无缝降级、无框架版本漂移。

### ADR-002：Embedding 用 Ollama bge-m3（本地），不用 sentence-transformers
- **背景**：HuggingFace 不可达；本机已装 Ollama 且含 `bge-m3`（1024 维，F16）。
- **决策**：Embedding 走 Ollama HTTP API，省去 torch 依赖与模型下载；`RETRIEVE_MIN_SCORE` 按 RRF 融合分重校准为 0.02（融合分上限 ≈ 2/61 ≈ 0.033）。

### ADR-003：向量库用自研 numpy 实现（接口对齐 Chroma/Milvus）
- **背景**：语料仅 347 块，numpy 点积 + 余弦归一化毫秒级完成；规避 chromadb 在 Python 3.14 的兼容风险。
- **决策**：`src/rag/vector_store.py` 提供 `add/query/persist/load`，接口与 Chroma 对齐，可平滑迁移。

### ADR-004：无专用 reranker，RRF 融合 + 可选 LLM 重排
- **背景**：Ollama registry 无 bge-reranker 资源（pull 404）。
- **决策**：默认 RRF 融合（k=60），`RERANK_ENABLED=false`；开启时走 LLM 重排。检索评测（Recall@10/MRR/NDCG）作为定版依据。

### ADR-005：会话状态（meta.step）优先于规则路由
- **背景**：售后"确认"阶段用户回复"确认"会被规则路由误判为闲聊。
- **决策**：编排器在路由后检查 `meta.step=="confirm"` 强制转售后 Agent。同类状态（skincare_ask）预留。

### ADR-006：售后"申请类 vs 咨询类"意图分流
- **背景**："退款多久到账"与"我要退货"都含"退款"，路由易混。
- **决策**：规则表按 政策咨询（能退吗/怎么退/多久/运费…）→ 售后申请（我要退货/申请/换货…）→ 其他 的优先级排序。

## 1. 踩坑记录

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | aiosqlite 进程退出挂起 | 连接未关闭，后台线程阻塞解释器退出 | 所有脚本/服务退出前 `close_db()` |
| 2 | 多轮会话状态丢失 | `create_session()` 总生成新 ID，未复用传入 ID | 支持 `create_session(session_id=...)` + INSERT OR IGNORE |
| 3 | DeepSeek 400 `tool role must follow tool_calls` | 工具循环未回填 assistant tool_calls 消息 | `_llm_loop` 按 OpenAI 协议补 assistant 消息 |
| 4 | 转人工工单 ID 同秒冲突 | `TR+时间戳` 粒度到秒 | 追加 4 位随机后缀 |
| 5 | `Event loop is closed`（测试/脚本） | httpx.AsyncClient 绑定首个事件循环，多次 asyncio.run 复用单例 | 客户端按事件循环懒创建 |
| 6 | 注入检测漏检"忽略以上所有指令" | 正则未覆盖插入语"所有" | 改为宽松匹配 `忽略.{0,8}(指令\|规则\|…)` |
| 7 | RRF 阈值 0.30 过滤全部结果 | 误用 cosine 阈值语义 | 校准为 0.02 并注释语义 |

## 2. 调优记录

### 检索层调优（W1 完成）

| 项 | 调整 | 效果 |
|----|------|------|
| RRF 融合阈值 | 0.30 → 0.02（按融合分上限 2/61≈0.033 校准） | 修复"全部结果被过滤" |
| 融合 TopK | 10 → 15 | Recall@10 80.6% → 92.8% |
| 检索标注修正 | 修正 6 条错误标注（如油皮产品误标敏感肌） | 指标反映真实相关性 |
| 最终指标（@10） | Recall 92.8% / MRR 0.884 / NDCG@5 0.804 | 全部达标（≥85%/0.7/0.75） |

### 情绪识别调优（W1 完成）

| 项 | 调整 | 效果 |
|----|------|------|
| 负面词表扩充 | +19 个常见不满表达（太慢/烦/假货/刺痛/质量差等） | negative 准确率 30% → 100%（30/30 标注集） |

### 路由与延迟调优（W3/W4 完成）

| 项 | 调整 | 效果 |
|----|------|------|
| 路由优先级 | 具体产品名 > 关键词 > 订单号正则（修复"退货 O2026..."被误判订单） | aftersale/logistics 场景 20%→100% |
| 商品关键词扩充 | 适合敏感肌/适合什么肤质/开封 等 → product_consult | 减少 LLM 分类调用（省 3s） |
| 分类结果缓存 | 同文本缓存意图 | 重复查询零成本 |
| 售后分流 | 政策咨询（能退吗/多久/审核）先于售后申请 | T044-T050 政策类 100% |
| SSE 流式 | 流式路径跳过工具预检，直接 chat_stream | TTFT 6.2s → **1.8-2.2s** |
| Embedding 驻留 | `keep_alive=10m` | 避免 Ollama 模型冷加载（2.4s→0.24s） |
