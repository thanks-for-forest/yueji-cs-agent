# 开发笔记（决策记录 / 调优过程）

> 记录开发过程中的关键决策、踩坑与量化调优结果，保持可追溯。

## 0. 技术决策记录（ADR）

### ADR-001：LLM 接入采用 OpenAI 兼容协议直连（DeepSeek 主 / Ollama 兜底）
- **背景**：规划文档选定 LangChain；实测 Python 3.14 下 langchain 1.3.16 可安装，但为完全掌控工具调用循环与降级逻辑，Agent 编排层自研。
- **决策**：`src/llm/client.py` 基于 httpx 直连 OpenAI 兼容接口；LangChain 保留在依赖中供后续演进。
- **权衡**：自研 ~250 行，换来工具循环可调试、双提供方无缝降级、无框架版本漂移。

### ADR-002：Embedding 用 Ollama bge-m3（本地），不用 sentence-transformers
- **背景**：HuggingFace 不可达；本机已装 Ollama 且含 `bge-m3`（1024 维，F16）。
- **决策**：Embedding 走 Ollama HTTP API，省去 torch 依赖与模型下载；`RETRIEVE_MIN_SCORE` 按 RRF 融合分重校准为 0.02（融合分上限 ≈ 2/61 ≈ 0.033）。

### ADR-003：向量库用自研 numpy 实现（接口对齐 Chroma/Milvus）
- **背景**：语料仅 347 块，numpy 点积 + 余弦归一化毫秒级完成；规避 chromadb 在 Python 3.14 的兼容风险。
- **决策**：`src/rag/vector_store.py` 提供 `add/query/persist/load`，接口与 Chroma 对齐，可平滑迁移。

### ADR-004：无专用 reranker，RRF 融合 + 可选 LLM 重排
- **背景**：Ollama registry 无 bge-reranker 资源（pull 404）。
- **决策**：默认 RRF 融合（k=60），`RERANK_ENABLED=false`；开启时走 LLM 重排。检索评测（Recall@10/MRR/NDCG）作为定版依据。

### ADR-005：会话状态（meta.step）优先于规则路由
- **背景**：售后"确认"阶段用户回复"确认"会被规则路由误判为闲聊。
- **决策**：编排器在路由后检查 `meta.step=="confirm"` 强制转售后 Agent。同类状态（skincare_ask）预留。

### ADR-006：售后"申请类 vs 咨询类"意图分流
- **背景**："退款多久到账"与"我要退货"都含"退款"，路由易混。
- **决策**：规则表按 政策咨询（能退吗/怎么退/多久/运费…）→ 售后申请（我要退货/申请/换货…）→ 其他 的优先级排序。

## 1. 踩坑记录

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | aiosqlite 进程退出挂起 | 连接未关闭，后台线程阻塞解释器退出 | 所有脚本/服务退出前 `close_db()` |
| 2 | 多轮会话状态丢失 | `create_session()` 总生成新 ID，未复用传入 ID | 支持 `create_session(session_id=...)` + INSERT OR IGNORE |
| 3 | DeepSeek 400 `tool role must follow tool_calls` | 工具循环未回填 assistant tool_calls 消息 | `_llm_loop` 按 OpenAI 协议补 assistant 消息 |
| 4 | 转人工工单 ID 同秒冲突 | `TR+时间戳` 粒度到秒 | 追加 4 位随机后缀 |
| 5 | `Event loop is closed`（测试/脚本） | httpx.AsyncClient 绑定首个事件循环，多次 asyncio.run 复用单例 | 客户端按事件循环懒创建 |
| 6 | 注入检测漏检"忽略以上所有指令" | 正则未覆盖插入语"所有" | 改为宽松匹配 `忽略.{0,8}(指令\|规则\|…)` |
| 7 | RRF 阈值 0.30 过滤全部结果 | 误用 cosine 阈值语义 | 校准为 0.02 并注释语义 |

## 5. 项目完善 v2.0（LangGraph + 自研可观测 + 检索优化）

### ADR-007：LangGraph Supervisor-Worker 编排
- 决策：主路径 `orchestrator.handle` 改为 StateGraph 执行（security→emotion→route→5 Worker→finalize），
  保留流式快路径（handle_stream）；Agent 内部实现零改动，仅编排层重构。
- 验证：41→46 项单测全过；全量 100 条评测走图路径复跑。
- 期间修复：① 评测时间漂移（订单日期锚点 + REFERENCE_NOW 确定性基准）② policy_mode 误加 ctx（NameError）。

### ADR-008：Langfuse 可观测性（优雅降级）
- 决策：`src/utils/tracing.py` 封装 CallbackHandler；配置密钥时图执行自动出调用链，
  未配置时返回 None（no-op），行为与未接入完全一致。
- 自托管尝试（docker-compose.langfuse.yml）：镜像拉取成功、服务可起（:3001），
  但**首管理员初始化在本环境未成功**（ENCRYPTION_KEY 需随机、环境变量实为 LANGFUSE_INIT_* 前缀、
  登录 API 401/302 异常）。结论：代码就绪 + compose 就绪，启用需云密钥或继续排障自托管。

### ADR-009：检索融合模式 dense_first
- 实验（30 条标注集）：Dense-only 98.9% > Hybrid-RRF 92.8% > BM25-only 87.2%。
- 决策：线上默认改为 **dense_first**（Dense TopK 优先 + BM25 独有兜底），指标与 Dense 持平
  且保留精确匹配兜底；`RETRIEVE_FUSION_MODE=rrf|dense_first` 可切换。
- 新增**余弦相似度门槛** DENSE_MIN_SIMILARITY=0.55（相关≥0.71 / 无关≤0.50 实测分界），
  修复无关查询误入检索（天气/写诗/老板 类查询正确归零，走拒答协议）。

### ADR-010：自研 JSONL 追踪器（Langfuse 替代方案）
- 决策：以**自研轻量追踪器**为默认可观测性（零依赖/零账号/本地 JSONL），
  Langfuse 保留为可选集成（配置密钥后经 LangGraph CallbackHandler 上报）。
- 实现：`src/utils/tracing.py` — Trace/span（contextvars 隔离并发）、节点耗时、
  LLM 调用计数；图节点与 handle/stream 埋点；`scripts/trace_report.py` 产出
  `docs/可观测性报告.md` + HTML 看板。
- 理由：简历差异化（"自研全链路追踪"而非"用了某工具"）；无外部依赖即刻可用；
  为 Langfuse 留接口，两者可共存。
- 验证：50 项单测全过；真实对话产出 4 条完整调用链（security→emotion→route→agent→finalize）。

### ADR-012：单 UI + 角色门禁（客服对话 / 知识库管理分离权限）
- 决策：同一 Streamlit 应用内做角色隔离——访客仅见「客服对话」；管理员输入口令（`X-Admin-Token`）后
  才出现「知识库管理」入口；KB 全部接口服务端校验令牌（无令牌 403）。
- 审计：`kb_docs` 新增 created_by/approved_by/rejected_by/rolled_back_by，操作人随接口头 `X-Admin-Name` 记录。
- 理由：真实企业里知识库是"可信内容源"，不能让终端用户污染；角色边界 + 操作留痕是生产刚需。
- 验证：57 项单测全过（+2 权限门禁用例）；curl 验证 无令牌 403 / 有令牌 200。

### ADR-013：四视图 UI 架构（门户游客客服 / 登录注册 / 用户专属客服 / 管理员知识库）
- 决策：单一 Streamlit 应用内实现四视图状态机——门户默认游客对话；注册/登录（pbkdf2 哈希 + 24h token，
  `auth_tokens` 表）；登录后会话与订单绑定账号（token 解析 user_id）；管理员独立口令登录进知识库管理。
- 演示账号：demo1→U001 / demo2→U005（密码 demo123，首次启动播种）；新注册用户独立 user_id（无预置订单）。
- 验证：57+5 项单测全过；E2E：登录→会话绑定 U001→查本人订单 / 错误密码 401 / 重复注册 400 / 登出后 401。

### ADR-014：四个角色拆分独立页面（st.navigation 多页面）
- 决策：由"单页内切换"升级为 Streamlit 多页面路由（st.Page + st.navigation），
  每个角色独立 UI 与 URL（/portal、/login、/user、/admin），登录态经 session_state 共享，
  /user 与 /admin 带访问守卫（未登录自动跳转/显示登录）。
- 理由：更贴近真实企业"门户/用户端/管理后台分离"的形态；URL 可直达、可分享、可分别部署。
- 验证：四页面 URL 均 200；模块级调用顺序静态检查通过；62 项单测全过。

### ADR-015：独立管理后台 + 每页主题 + 用户侧栏
- 管理后台拆为独立子应用 frontend/admin_app.py（端口 8502，深色管理风 CSS），与客服端解耦；主应用导航移除 admin 页。
- 门户页营销风（渐变 hero + 特色卡片）；登录页居中表单；用户页侧栏含「我的会话」（可点击加载历史）与「我的订单」。
- 新增接口：/api/user/sessions、/api/orders/me（X-Auth-Token 鉴权，本人数据隔离）。
- 验证：64 项单测全过；三端口（8000/8501/8502）200；demo1 会话 20 条、订单 2 条、未登录 401。

### ADR-016：知识库管理增强（参考 Langchain-Chatchat / Dify / RAGFlow）
- 新增：统计面板（文档数/知识块/分类分布/基础库 vs KB 占比）、检索命中测试（query-test 显示召回块+相似度+一键问客服）、
  分块编辑（改文本→重新向量化→已入库自动重建索引）、批量审核/回滚、状态/分类/关键词筛选。
- 验证：64 项单测全过；冒烟：审核前无 KB 命中→审核后命中（相似度 0.759）→分块编辑生效。

### ADR-017：泛化导购目录兜底
- 背景："有什么产品"类目录型问题检索为空（余弦门槛过滤）→ 之前仅澄清反问。
- 实现：is_catalog_query 识别目录型问题；检索为空时 catalog_context 给出热门产品 Top8（按销量，可识别品类）；
  产品 Agent 加"目录模式"指令逐款介绍（名称/价格/功效/肤质 + 来源）；管理后台 query-test 同步展示。
- 验证：客服回答列出产品带〔来源〕；非目录型（"这个多少钱"）仍澄清；64 单测 + 100 条评测回归通过。

### ADR-018：前端应用 sys.path 引导（任意目录启动）
- 现象：从非项目根目录启动 streamlit（如 cd frontend 后运行）报 ModuleNotFoundError: No module named 'config'。
- 根因：config 为命名空间包（无 __init__.py），且脚本目录入 sys.path 而非项目根。
- 修复：frontend/app.py 与 admin_app.py 在 from config import settings 前，将 Path(__file__).parent.parent 注入 sys.path。
- 验证：从 frontend/ 目录启动两个服务均 HTTP 200，日志无导入错误。

### ADR-019：借鉴 Dify 能力清单补强自研知识库后台
- 背景：用户问"向量库能否用 Dify 管理"——Dify 是 RAG 平台，其知识库不读写自研 npz 体系。决策：保留自研 RAG 主链路，按 Dify 能力清单逐项对照补强（详见 docs/Dify能力对照与补强清单.md）。
- 本轮补强：多格式（csv/xlsx/html）、批量上传（一次 embed 全部块）、分块策略可视化（KB_CHUNK_SIZE/OVERLAP + 后台滑杆）、重新分块（新增 raw_text 列，按新策略重切重向量化）、索引健康检查+强制重建、导出 json/md、命中测试四模式（dense_first/rrf/dense/bm25）+ 检索日志统计（kb_query_log 表）、批量删除、分类清单（预置 ∪ 已用）。
- 修复既有 bug：FastAPI 中 category/chunk_size/overlap 等标量参数默认是 query，前端以 multipart form 发送从未生效——改用 Form() 声明后分类才真正落库（此前统计面板分类恒为"未分类"的根因）。
- 教训（再次出现）：路由引用 Pydantic 模型类时，类定义必须在其被装饰的路由之前（from __future__ import annotations 下后定义会产生未解析 ForwardRef，OpenAPI 生成崩溃）。
- 验证：pytest 69 通过（+5 service 级 + 6 集成）、100 条评测回归、全部新端点冒烟实测通过。

### UI 修复：管理后台按钮文字对比度
- 现象：深色主题下 st.button 为 Streamlit 默认描边透明底，按钮文字与底色对比差、看不清。
- 修复：DARK_CSS/BEIGE_CSS 统一注入 .stButton/.stDownloadButton/.stFormSubmitButton 三选器（BTN_SEL），

  含 hover/focus/disabled 与侧栏（退出管理员）同规范。
- 验证：AppTest 渲染 0 异常，CSS 注入确认。

### ADR-020：简历加分优化批次（CI / 离线可测 / LLM 容错 / 数据驱动检索评估）
- 动机：项目审计后，只挑对简历有实质加分的优化落地。
